\section{Introdução}

Esta documentação se refere ao projeto feito no Trabalho Prático 1, da disciplina PROJETO E ANÁLISE DE ALGORITMOS, ministrada na Universidade Federal de Viçosa (UFV) -- Campus Florestal. No trabalho, foi proposta a implementação de um programa em linguagem C para a resolução exaustiva de um problema de exploração de labirintos pautado no paradigma de \textbf{Backtracking}, visando determinar a existência de uma rota viável entre a posição inicial do aventureiro e a câmara que abriga um baú de tesouros, e a montagem de tabelas e gráficos para analisar seu tempo de execução, a fim de aprender sobre complexidade de algoritmos. O projeto descrito neste documento está versionado e documentado no repositório oficial do grupo.

O labirinto bidimensional impõe restrições essenciais ao aventureiro:
\begin{itemize}
    \item Cada sala (célula da matriz) pode ser visitada no máximo uma única vez durante a trajetória, impedindo a ocorrência de ciclos;
    \item O baú misterioso somente pode ser destrancado caso o aventureiro colete a quantidade exata de chaves exigida;
    \item Apenas movimentos cardeais ortogonais são admitidos (Cima, Baixo, Esquerda e Direita), sendo vedados saltos ou diagonais;
    \item Paredes intransponíveis não podem ser atravessadas.
\end{itemize}

Algumas bibliotecas padrão da linguagem C (C99 nativa) foram utilizadas para o programa, elas são “stdio.h”, “stdlib.h”, “string.h”, “time.h” e “unistd.h”. “time.h” foi utilizada para capturar o tempo de máquina e calcular a duração exata das execuções para o benchmark, “stdlib.h” foi utilizada para gerenciamento dinâmico de memória e números aleatórios no gerador de labirintos, “stdio.h” para leitura e escrita de arquivos formatados, “string.h” para manipulação de cadeias de caracteres e argumentos de CLI, e “unistd.h” para o controle de temporização da animação no terminal. O programa foi estruturado em módulos independentes em C, separando o algoritmo de busca, as regras de navegação, a interface de usuário e a infraestrutura de medição de desempenho.

\section{Desenvolvimento}

\subsection{“mapa.c” e “mapa.h”}
Nestes arquivos foi descrita a estrutura que armazena a matriz do labirinto, as coordenadas de início, do baú e a quantidade de chaves. Foram criadas as seguintes funções:

\textbf{“carrega\_labirinto”}: Lê o arquivo de texto formatado, aloca dinamicamente a matriz bidimensional de células e preenche as informações topológicas.

\textbf{“libera\_labirinto”}: Libera a memória alocada para a matriz e para a estrutura de dados.

\textbf{“imprime\_labirinto”}: Imprime o estado textual da grade para conferência.

\subsection{“backtracking.c” e “backtracking.h”}
Nestes arquivos foi descrito o motor de busca em profundidade sistemático com retrocesso recursivo (\textit{backtracking}). Em “backtracking.h” foram declaradas as funções para serem utilizadas na “main.c”:

\textbf{“resolver\_labirinto”}: Inicializa a matriz de marcação de visitados, dispara a recursão a partir da posição inicial com zero chaves coletadas e gerencia o encerramento ao alcançar o baú.

\textbf{“backtracking\_recursivo”}: Executa o passo recursivo do algoritmo. A cada célula, verifica se o baú foi alcançado com a meta de chaves atendida; caso contrário, ramifica nas direções permitidas, marca a célula atual no vetor de visitados, invoca a próxima chamada recursiva e, no retorno (\textit{backtrack}), desmarca a célula para permitir outros ramos de busca.

\subsection{“navegacao.c” e “cli.c”}

O desenvolvimento deste módulo teve como objetivo central desacoplar totalmente as regras de transição física do aventureiro sobre o labirinto e o tratamento dos argumentos de linha de comando em relação ao motor de busca por \textit{backtracking}. Essa divisão permitiu que os demais membros do grupo integrassem o algoritmo de busca recursiva, as métricas e a interface visual sem necessidade de manipular diretamente detalhes geométricos ou convenções de entrada do sistema operacional.

A estrutura de dados \texttt{Opcoes} atua como o ponto de unificação das configurações do programa, armazenando o arquivo de entrada e as flags binárias ativadas pelo usuário:

\begin{lstlisting}[language=C, caption={Estrutura de dados Opcoes para parametrização via linha de comando.}]
typedef struct {
    const char *arquivo_entrada; /* Caminho do arquivo .txt do labirinto */
    int modo_globo;              /* 1: movimentacao toroidal (--globo) */
    int modo_todos;              /* 1: busca exaustiva de todos os caminhos (--todos) */
    int modo_analise;            /* 1: exibicao de nos e profundidade (--analise) */
    int modo_visual;             /* 1: animacao colorida ANSI no terminal (--visual) */
} Opcoes;
\end{lstlisting}

A função \textbf{“cli\_parse”} é responsável por iterar sequencialmente sobre o vetor \texttt{argv} a partir do índice 1. Argumentos com o prefixo \texttt{--} são mapeados para suas respectivas variáveis na estrutura \texttt{Opcoes}. O primeiro argumento posicional sem prefixo é capturado como o caminho do arquivo do labirinto. Como medida de robustez, o grupo optou por tolerar opções desconhecidas emitindo um aviso amigável em \texttt{stderr} sem abortar a execução imediatamente. Caso nenhum arquivo de entrada seja fornecido, a função \textbf{“cli\_usage”} é acionada automaticamente para imprimir no console a sintaxe correta de invocação e os parâmetros aceitos, retornando código 0 para encerrar o programa de forma segura.

Para a movimentação do aventureiro, foram estabelecidos dois modos operacionais: o modo euclidiano padrão e o modo toroidal (\textit{Modo Globo}). A fim de evitar encadeamentos repetitivos de estruturas condicionais (\texttt{if/else}) durante as milhões de chamadas recursivas do \textit{backtracking}, os deslocamentos cardeais foram mapeados em vetores bidimensionais estáticos de complexidade $O(1)$:

\begin{lstlisting}[language=C, caption={Vetores constantes para deslocamento ortogonal (Cima, Baixo, Esquerda, Direita).}]
const int DIRECOES_LIN[NUM_DIRECOES] = {-1,  1,  0,  0};
const int DIRECOES_COL[NUM_DIRECOES] = { 0,  0, -1,  1};
\end{lstlisting}

A função \textbf{“movimento\_valido”} avalia se a célula candidata $(lin, col)$ atende rigorosamente às três restrições fundamentais do problema:
\begin{enumerate}
    \item Estar contida nos limites dimensionais da matriz ($0 \le lin < \text{linhas}$ e $0 \le col < \text{colunas}$);
    \item Não constituir uma barreira física intransponível (\texttt{grade[lin][col] != PAREDE});
    \item Não ter sido visitada no ramo de busca corrente (\texttt{visitado[lin][col] == 0}).
\end{enumerate}

\begin{lstlisting}[language=C, caption={Validação de coordenadas no modo padrão com avaliação em curto-circuito.}]
int movimento_valido(const Labirinto *lab, int **visitado, int lin, int col) {
    if (lin < 0 || lin >= lab->linhas)  return 0;
    if (col < 0 || col >= lab->colunas) return 0;
    if (lab->grade[lin][col] == PAREDE) return 0;
    if (visitado[lin][col]) return 0;
    return 1;
}
\end{lstlisting}

\textbf{Decisão de Implementação:} A checagem dos limites precede estritamente o acesso à matriz de células. Pelo mecanismo de curto-circuito das expressões lógicas em C (\textit{short-circuit evaluation}), caso os índices sejam negativos ou ultrapassem as dimensões alocadas, a função encerra imediatamente retornando 0 antes de desreferenciar a memória, prevenindo falhas de segmentação (\textit{segmentation fault}) e comportamentos indefinidos.

A função \textbf{“proxima\_posicao”} calcula a nova posição somando o vetor de deslocamento e delega sua viabilidade diretamente a \textbf{“movimento\_valido”}.

Para o \textbf{Modo Globo}, o mapa deixa de ter bordas bloqueantes e passa a se comportar como uma superfície toroidal contínua, onde transpor a borda leste faz o personagem reaparecer na margem oeste, e transpor a borda sul o faz ressurgir na borda norte. A transição foi modelada matematicamente pela congruência modular:
\begin{align}
    lin' &= (lin + \Delta_{lin} + L) \pmod L \\
    col' &= (col + \Delta_{col} + C) \pmod C
\end{align}

\begin{lstlisting}[language=C, caption={Cálculo toroidal em O(1) e validação de células no Modo Globo.}]
int proxima_posicao_globo(const Labirinto *lab, int **visitado, int lin,
                          int col, int d, int *prox_lin, int *prox_col) {
    *prox_lin = (lin + DIRECOES_LIN[d] + lab->linhas)  % lab->linhas;
    *prox_col = (col + DIRECOES_COL[d] + lab->colunas) % lab->colunas;
    return movimento_valido_globo(lab, visitado, *prox_lin, *prox_col);
}

int movimento_valido_globo(const Labirinto *lab, int **visitado, int lin, int col) {
    if (lab->grade[lin][col] == PAREDE) return 0;
    if (visitado[lin][col]) return 0;
    return 1;
}
\end{lstlisting}

\textbf{Fundamentação Algébrica:} No padrão C99 (ISO/IEC 9899 §6.5.5), o operador binário \texttt{\%} opera com truncamento em direção a zero, preservando o sinal algébrico negativo caso o dividendo seja negativo (por exemplo, \texttt{-1 \% 10 == -1}). A adição da dimensão total ($L$ e $C$) antes da aplicação do resto garante um valor estritamente não-negativo sem alterar a classe de congruência. Uma vez normalizadas as coordenadas no intervalo $[0, L-1]$ e $[0, C-1]$, a função \textbf{“movimento\_valido\_globo”} dispensa o teste de fronteiras externas, limitando-se a checar paredes e células já visitadas.

\subsection{“analise.c” e “visualizador.c”}

Nestes arquivos foram implementados o módulo de instrumentação de desempenho e o visualizador em terminal com sequências de escape ANSI, ambos desacoplados da lógica de decisão do \textit{backtracking}.

\subsubsection{Módulo de análise de métricas}

As métricas são agrupadas na estrutura \texttt{AnaliseMetricas}, que armazena o total de chamadas recursivas, a profundidade corrente e máxima, o número de podas e o número de retrocessos. Foram criadas as seguintes funções:

\textbf{“analise\_iniciar”}: Zera todos os contadores da estrutura antes da execução da busca.

\textbf{“analise\_registrar\_chamada”}: Chamada a cada entrada em \textbf{“backtracking\_recursivo”}. Incrementa o total de chamadas, atualiza a profundidade corrente e, caso esta supere o máximo já observado, atualiza a profundidade máxima.

\textbf{“analise\_registrar\_poda”} e \textbf{“analise\_registrar\_retrocesso”}: Incrementam, respectivamente, o contador de ramificações descartadas e o de retornos (\textit{backtracks}) da recursão.

\textbf{“analise\_imprimir”}: Exibe o relatório final no terminal quando a opção \texttt{--analise} está ativa.

\begin{lstlisting}[language=C, caption={Registro de chamadas e profundidade máxima em analise.c.}]
void analise_registrar_chamada(AnaliseMetricas *m, int profundidade) {
    if (!m) return;
    m->chamadas_recursivas++;
    m->profundidade_atual = profundidade;
    if (profundidade > m->profundidade_maxima)
        m->profundidade_maxima = profundidade;
}
\end{lstlisting}

\textbf{Decisão de Implementação:} Cada registro consiste apenas em um incremento, uma atribuição e uma comparação, todos de custo $O(1)$. Assim, a instrumentação não altera a complexidade assintótica do algoritmo, e manter as métricas em um módulo separado evita misturar contabilidade com a lógica de busca. A verificação \texttt{if (!m) return;} permite desativar a análise passando ponteiro nulo.

\subsubsection{Visualizador ANSI}

O módulo \texttt{visualizador.c} renderiza o labirinto colorido no terminal. As constantes de cor (\texttt{ANSI\_BG\_*}, \texttt{ANSI\_FG\_*}, \texttt{ANSI\_RESET}) foram definidas em \texttt{visualizador.h} como macros de sequências de escape do tipo \texttt{\textbackslash033[<código>m}. As funções do módulo são:

\textbf{“visualizador\_limpar\_tela”}: Emite a sequência \texttt{\textbackslash033[H\textbackslash033[J}, que move o cursor para o canto superior esquerdo (\texttt{\textbackslash033[H}) e apaga o conteúdo dali até o fim da tela (\texttt{\textbackslash033[J}), permitindo redesenhar sobre o mesmo local.

\textbf{“visualizador\_ocultar\_cursor”} e \textbf{“visualizador\_mostrar\_cursor”}: Usam \texttt{\textbackslash033[?25l} e \texttt{\textbackslash033[?25h} para esconder o cursor durante a animação e restaurá-lo ao final, evitando cintilação.

\textbf{“visualizador\_desenhar”}: Desenha um quadro. Cria uma matriz auxiliar marcando as células pertencentes ao caminho, limpa a tela e imprime cada célula com sua cor. A posição atual é destacada com \texttt{@} e as demais células do caminho com \texttt{*}.

\textbf{“visualizador\_desenhar\_caminho\_final”}: Desenha o labirinto com o caminho completo, sem destacar posição atual.

\textbf{“visualizador\_animar\_caminho”}: Percorre o caminho encontrado e desenha um quadro por passo.

for (int k = 0; k < caminho->tamanho; k++) {

Como a animação reproduz o caminho já encontrado, seu custo adicional é $O(k \cdot L \cdot C)$ para um caminho de $k$ passos em uma grade $L \times C$, e ocorre somente quando a opção \texttt{--visual} é informada, não interferindo nas medições de tempo do \textit{benchmark}.

\section{Conclusão}

De forma geral, foram implementados módulos e códigos, de forma organizada, comentada e de fácil entendimento para o problema solicitado pelo trabalho. Foi decidida uma abordagem modular e interativa com o usuário via terminal, que ao fim foi uma ótima opção abstraindo o código, e o deixando mais fácil de ser visualizado e compreendido pelo usuário e pelo avaliador.

Os resultados experimentais saíram assim como o esperado pela teoria da computação: em labirintos pequenos e médios, o algoritmo de backtracking encontra a solução com rapidez; em labirintos densos e de maiores dimensões, o tempo cresce consideravelmente em virtude da complexidade combinatorial do problema. No que tange às extensões propostas, a formulação da movimentação toroidal (Modo Globo) comprovou que transições topológicas complexas podem ser calculadas em custo temporal unitário $O(1)$ por meio de aritmética modular, sem onerar o consumo de memória do sistema. Sendo assim, o trabalho de forma geral atende integralmente às exigências passadas pelo Professor do curso de Projeto e Análise de Algoritmos (PAA).
