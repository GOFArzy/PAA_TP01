\section{Introdução}

Esta documentação se refere ao projeto feito no Trabalho Prático 1, da disciplina PROJETO E ANÁLISE DE ALGORITMOS, ministrada na Universidade Federal de Viçosa (UFV) -- Campus Florestal. No trabalho, foi proposta a implementação de um programa em linguagem C para a resolução exaustiva de um problema de exploração de labirintos pautado no paradigma de \textbf{Backtracking}, visando determinar a existência de uma rota viável entre a posição inicial do aventureiro e a câmara que abriga um baú de tesouros, e a montagem de tabelas e gráficos para analisar seu tempo de execução, a fim de aprender sobre complexidade de algoritmos. O projeto descrito neste documento está versionado e documentado no repositório oficial do grupo.

O labirinto bidimensional impõe restrições essenciais ao aventureiro:
\begin{itemize}
    \item Cada sala (célula da matriz) pode ser visitada no máximo uma única vez durante a trajetória, impedindo a ocorrência de ciclos;
    \item O baú misterioso somente pode ser destrancado caso o aventureiro colete a quantidade exata de chaves exigida;
    \item Apenas movimentos cardeais ortogonais são admitidos (Cima, Baixo, Esquerda e Direita), sendo vedados saltos ou diagonais;
    \item Paredes intransponíveis não podem ser atravessadas.
\end{itemize}

Algumas bibliotecas padrão da linguagem C (C99 nativa) foram utilizadas para o programa, elas são “stdio.h”, “stdlib.h”, “string.h”, “time.h” e “unistd.h”. “time.h” foi utilizada para capturar o tempo de máquina e calcular a duração exata das execuções para o benchmark, “stdlib.h” foi utilizada para gerenciamento dinâmico de memória e números aleatórios no gerador de labirintos, “stdio.h” para leitura e escrita de arquivos formatados, “string.h” para manipulação de cadeias de caracteres e argumentos de CLI, e “unistd.h” para o controle de temporização da animação no terminal. O programa foi estruturado em módulos independentes em C, separando o algoritmo de busca, as regras de navegação, a interface de usuário e a infraestrutura de medição de desempenho.

\section{Desenvolvimento}

\subsection{“mapa.c” e “mapa.h”}
Nestes arquivos foi descrita a estrutura que armazena a matriz do labirinto, as coordenadas de início, do baú e a quantidade de chaves. Foram criadas as seguintes funções:

\textbf{“carrega\_labirinto”}: Lê o arquivo de texto formatado, aloca dinamicamente a matriz bidimensional de células e preenche as informações topológicas.

\textbf{“libera\_labirinto”}: Libera a memória alocada para a matriz e para a estrutura de dados.

\textbf{“imprime\_labirinto”}: Imprime o estado textual da grade para conferência.

\subsection{“backtracking.c” e “backtracking.h”}
Nestes arquivos foi descrito o motor de busca em profundidade sistemático com retrocesso recursivo (\textit{backtracking}). Em “backtracking.h” foram declaradas as funções para serem utilizadas na “main.c”:

\textbf{“resolver\_labirinto”}: Inicializa a matriz de marcação de visitados, dispara a recursão a partir da posição inicial com zero chaves coletadas e gerencia o encerramento ao alcançar o baú.

\textbf{“backtracking\_recursivo”}: Executa o passo recursivo do algoritmo. A cada célula, verifica se o baú foi alcançado com a meta de chaves atendida; caso contrário, ramifica nas direções permitidas, marca a célula atual no vetor de visitados, invoca a próxima chamada recursiva e, no retorno (\textit{backtrack}), desmarca a célula para permitir outros ramos de busca.

\subsection{“navegacao.c” e “cli.c”}
Nestes arquivos foram implementadas as regras de transição física do aventureiro sobre o mapa e o processamento de parâmetros da linha de comando, desacoplando o algoritmo de busca da geometria e da interface do sistema operacional.

Em “navegacao.h” e “navegacao.c” foram criadas as seguintes funções:

\textbf{“movimento\_valido”}: Verifica se o movimento ortogonal para uma dada coordenada respeita os limites da matriz, se a célula destino não é uma parede e se ela ainda não foi visitada no caminho atual.

\textbf{“proxima\_posicao\_globo”}: Implementa a transição em geometria toroidal (\textbf{Modo Globo}), fazendo com que o aventureiro ultrapasse as bordas do mapa e ressurja na margem oposta.

Para otimizar o tempo de computação das milhões de transições que o algoritmo executa na árvore de busca, as quatro direções cardeais ortogonais foram formalizadas em vetores constantes de deslocamento com complexidade $O(1)$:

\begin{lstlisting}[language=C, caption={Vetores de deslocamento ortogonal constante.}]
const int DIRECOES_LIN[4] = {-1,  1,  0,  0}; /* Cima, Baixo, Esq, Dir */
const int DIRECOES_COL[4] = { 0,  0, -1,  1};
\end{lstlisting}

\begin{lstlisting}[language=C, caption={Validação de movimento padrão com verificação preventiva de limites.}]
int movimento_valido(const Labirinto *lab, int **visitado, int lin, int col) {
    if (lin < 0 || lin >= lab->linhas)  return 0;
    if (col < 0 || col >= lab->colunas) return 0;
    if (lab->grade[lin][col] == PAREDE) return 0;
    if (visitado[lin][col]) return 0;
    return 1;
}
\end{lstlisting}

\textbf{Decisão de Projeto:} A verificação dos limites dimensionais (\texttt{lin} e \texttt{col}) antecede rigorosamente o acesso à matriz de células (\texttt{lab->grade[lin][col]}). Em linguagem C, a inversão dessa ordem acarretaria violação de memória (\textit{segmentation fault}) por indexação negativa ou fora dos limites alocados.

Para o Modo Globo, a aritmética toroidal foi implementada garantindo estritamente congruência positiva:
\begin{align}
    lin' &= (lin + \Delta_{lin} + L) \pmod L \\
    col' &= (col + \Delta_{col} + C) \pmod C
\end{align}

\begin{lstlisting}[language=C, caption={Cálculo de transição toroidal em tempo O(1).}]
int proxima_posicao_globo(const Labirinto *lab, int **visitado, int lin,
                          int col, int d, int *prox_lin, int *prox_col) {
    *prox_lin = (lin + DIRECOES_LIN[d] + lab->linhas)  % lab->linhas;
    *prox_col = (col + DIRECOES_COL[d] + lab->colunas) % lab->colunas;
    return movimento_valido_globo(lab, visitado, *prox_lin, *prox_col);
}
\end{lstlisting}

\textbf{Obs:} A adição prévia da dimensão total ($L$ e $C$) antes do operador binário \texttt{\%} anula eventuais valores negativos provenientes de deslocamentos para cima ou esquerda, uma vez que o padrão C99 preserva o sinal negativo em operações de resto.

No arquivo “cli.c”, foi implementada a função:

\textbf{“cli\_parse”}: Interpreta os parâmetros passados pelo terminal preenchendo a estrutura \texttt{Opcoes} (\texttt{--globo}, \texttt{--todos}, \texttt{--analise}, \texttt{--visual}), isolando opções desconhecidas e exibindo instruções de uso caso o arquivo do labirinto não seja especificado.

\subsection{“analise.c” e “visualizador.c”}
Nestes arquivos foi implementada a instrumentação de desempenho computacional e a interface visual interativa em terminal:

\textbf{“analise\_registrar\_chamada”}: Contabiliza a quantidade de nós visitados e a profundidade máxima alcançada pela pilha de recursão.

\textbf{“visualizar\_passo”}: Utiliza sequências de escape ANSI para colorir e atualizar a grade do labirinto no terminal quadro a quadro, conferindo efeito de animação da busca.

\subsection{“saida.c”, “benchmark.c” e “main.c”}
\textbf{“imprime\_caminho”}: Formata a rota percorrida no padrão exigido pela especificação: $[l_1,c_1],[l_2,c_2],\dots,[l_k,c_k]$.

\textbf{“executa\_benchmark”}: Realiza baterias de testes temporizadas com a biblioteca \texttt{time.h}, permitindo avaliar a curva de crescimento do tempo computacional.

\textbf{“main”}: Orquestra o fluxo de execução, leitura de argumentos, inicialização do labirinto, chamada ao resolvedor e impressão dos relatórios.

\section{Conclusão}

De forma geral, foram implementados módulos e códigos, de forma organizada, comentada e de fácil entendimento para o problema solicitado pelo trabalho. Foi decidida uma abordagem modular e interativa com o usuário via terminal, que ao fim foi uma ótima opção abstraindo o código, e o deixando mais fácil de ser visualizado e compreendido pelo usuário e pelo avaliador.

Os resultados experimentais saíram assim como o esperado pela teoria da computação: em labirintos pequenos e médios, o algoritmo de backtracking encontra a solução com rapidez; em labirintos densos e de maiores dimensões, o tempo cresce consideravelmente em virtude da complexidade combinatorial do problema. No que tange às extensões propostas, a formulação da movimentação toroidal (Modo Globo) comprovou que transições topológicas complexas podem ser calculadas em custo temporal unitário $O(1)$ por meio de aritmética modular, sem onerar o consumo de memória do sistema. Sendo assim, o trabalho de forma geral atende integralmente às exigências passadas pelo Professor do curso de Projeto e Análise de Algoritmos (PAA).
